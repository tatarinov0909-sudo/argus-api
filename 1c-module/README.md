# Аргус — модуль 1С

Для 1С:Управление торговлей **10.3** (обычные формы), платформа 8.3.

## Здесь один файл

**`СинхронизацияАргус.bsl`** — весь модуль. Подключается к
`https://api.argus-ai.online` по ключу интеграции и отправляет контрагентов,
номенклатуру, накладные и остатки. Документы 1С не создаёт и не меняет:
**только читает и передаёт наружу** по HTTPS.

Раньше файлов было два — второй писал JSON на диск, чтобы посмотреть данные
до отправки. Он слит сюда: то же самое делают кнопки **«Проверить базу»**
(сводка на экран, ничего не пишет) и **«Выгрузить в файл»** (тот же JSON на
диск). Держать две обработки, собирающие одно и то же двумя разными кусками
кода, — верный способ однажды получить в файле одно, а на сервере другое.

## Если `.epf` уже собран — просто обновить

Так и есть у отца: `C:\Users\User7\Desktop\АргусСинхронизация.epf`, четыре
кнопки в нём уже работают. Файл нужно **править на месте**, новый не создавать.

1. На той же машине: **Конфигуратор** → «Файл» → «Открыть» → выбрать этот `.epf`
2. Слева в дереве: «Формы» → двойной клик на форме → откроется картинка формы
3. Внизу окна вкладка **«Модуль»** → выделить весь текст (Ctrl+A) → вставить
   поверх новый из `СинхронизацияАргус.bsl` (Ctrl+A, Ctrl+V)
4. Вернуться на вкладку **«Диалог»** и добавить три кнопки. Каждая делается
   одинаково: правой кнопкой на форме → «Вставить элемент управления» →
   «Кнопка» → в свойствах справа заполнить «Заголовок» и «Действие»:

   | Заголовок (что видно) | Действие (что вписать) |
   |---|---|
   | Проверить базу | `ПроверитьБазуВыполнить` |
   | Отправить остатки | `ОтправитьОстаткиВыполнить` |
   | Выгрузить в файл | `ВыгрузитьВФайлВыполнить` |

   Поля ввода добавлять не нужно — путь файла зашит в модуле.
5. **Ctrl+S** → закрыть Конфигуратор
6. Проверить: открыть тот же `.epf` уже в 1С:Предприятии (не в Конфигураторе):
   «Файл» → «Открыть» → ключ → «Подключиться» → **«Проверить базу»**

Если при сохранении 1С ругается красным — не гадать, прислать мне текст ошибки
целиком: там всегда есть имя и номер строки, по ним видно причину за минуту.

## Как собрать `.epf` с нуля (если его нет)

Внешняя обработка — отдельный файл, конфигурация базы не меняется.

1. Конфигуратор → **Файл → Новый → Внешняя обработка**
2. Имя: `АргусСинхронизация`
3. Правой кнопкой на «Формы» → **Добавить** → Форма обработки →
   **Готово** (обычная форма, не управляемая)
4. На форму положить:
   - поле ввода, реквизит формы **`КлючИнтеграции`**, тип Строка
   - надпись (Label), реквизит формы **`СтатусПодключения`**, тип Строка —
     просто для отображения текста, править вручную не нужно
   - семь кнопок, у каждой в свойстве «Действие» указать:
     - **`ПодключитьсяВыполнить`**
     - **`ПроверитьБазуВыполнить`** — ничего не отправляет, показывает, что
       модуль вообще нашёл в этой базе. Нажать первой.
     - **`ОтправитьКонтрагентовВыполнить`**
     - **`ОтправитьНоменклатуруВыполнить`**
     - **`ОтправитьНакладныеВыполнить`**
     - **`ОтправитьОстаткиВыполнить`**
     - **`ВыгрузитьВФайлВыполнить`** — записать всё в JSON на диск, ничего
       не отправляя
5. Открыть модуль формы, вставить весь текст из `СинхронизацияАргус.bsl`
6. **Файл → Сохранить как** → `АргусСинхронизация.epf`

## Как запустить

1. **Файл → Открыть** → `АргусСинхронизация.epf`
2. Ввести ключ интеграции (выдаёт владелец склада — сейчас его можно
   получить только через меня напрямую, кнопки в личном кабинете под
   это ещё нет) → **«Подключиться»**
3. **«Отправить контрагентов»** — сначала их, они нужны для сопоставления
   товаров с компанией-продавцом
4. **«Отправить номенклатуру»** — отправляется пачками по 500 позиций

После каждой отправки — окно со сводкой: сколько создано, обновлено,
и сколько с ошибкой.

## Важная оговорка про номенклатуру

Функция сбора номенклатуры читает реквизит `ГоловнойКонтрагент` —
это **не стандартный** реквизит УТ 10.3. В большинстве баз товар не
привязан к конкретному контрагенту напрямую (в отличие от модели
Аргуса, где товар всегда принадлежит продавцу). Если такого реквизита
в вашей базе нет — при отправке будет много ошибок «компания не найдена».
Это ожидаемо, не баг: значит, привязку товара к продавцу придётся
сделать иначе, обсудим отдельно, когда увидим реальную картину.

Вес пересчитывается из килограммов (стандарт УТ 10.3) в граммы —
если в вашей базе единица другая, поправьте до первой реальной отправки.

## Автозапуск по расписанию (Планировщик заданий Windows)

Вместо ручного нажатия трёх кнопок обработка теперь умеет отработать сама:
если `АргусСинхронизация.epf` запущен с параметром командной строки `/C`,
модуль читает его как ключ интеграции, молча (без диалоговых окон)
подключается и отправляет контрагентов → номенклатуру → накладные, пишет
результат в файл `argus_sync.log` рядом с собой и сам закрывает 1С. Обычное
открытие через «Файл → Открыть» не меняется — это работает только при
запуске из командной строки.

**Это касается сервера 1С клиента** — все шаги ниже выполняются вручную по
RDP на той же машине, где стоит база (или через кого-то с доступом к ней).
Из этой сессии Claude Code нет и не может быть прямого доступа к этому
серверу.

Шаги:

1. Скопируйте на сервер 1С папку с `АргусСинхронизация.epf` и шаблон
   [`АвтозапускСинхронизации.bat.example`](АвтозапускСинхронизации.bat.example)
   из этого репозитория.
2. Переименуйте `.bat.example` → `.bat`, заполните все `<ПЛЕЙСХОЛДЕРЫ>`
   реальными путём к `1cv8.exe`, адресом сервера/базы, логином и паролем
   1С-пользователя, ключом интеграции Аргуса (выдаётся в личном кабинете
   владельца) и путём к `.epf`.
3. Проверьте `.bat` вручную двойным щелчком — он должен молча отработать за
   несколько секунд и закрыться; проверьте `argus_sync.log` рядом.
4. Зарегистрируйте в Планировщике (пример — раз в 30 минут, поправьте
   `/SC MINUTE /MO 30` под нужный интервал; 1–2 минуты — идеал по нагрузке
   на 1С, но каждый запуск занимает лицензию на время сеанса, поэтому
   разумный компромисс — 15–30 минут):

   ```
   schtasks /Create /TN "Argus1CSync" /TR "C:\ArgusSync\argus_sync.bat" ^
     /SC MINUTE /MO 30 /RU "<ПОЛЬЗОВАТЕЛЬ_WINDOWS>" /RP "<ПАРОЛЬ_WINDOWS>" /RL HIGHEST
   ```

   Пользователь Windows, под которым выполняется задание, должен иметь
   право «Вход в качестве пакетного задания» (Log on as a batch job) —
   Планировщик выдаст об этом явную ошибку при регистрации, если права нет.

5. Снять/поправить задание: `schtasks /Delete /TN "Argus1CSync" /F` или
   `schtasks /Change /TN "Argus1CSync" ...`.

**Известные ограничения метода** (не наша недоработка, так устроен 1cv8.exe):
пароль 1С-пользователя лежит в открытом виде внутри `.bat`; каждый запуск
занимает полноценную лицензию 1С на время сеанса; секунды недостижимы —
`.epf` это разовый процесс, который стартует и умирает.

## Возможные препятствия

- Открытие внешних обработок может быть запрещено политикой базы
- **Сеть**: неизвестно, пускает ли эта 1С исходящий HTTPS наружу —
  выяснится только на первом запуске «Подключиться»
- Если конфигурация доработана, состав реквизитов может отличаться —
  код это переживёт (кроме `ГоловнойКонтрагент`, см. выше), но часть
  полей приедет пустой


## Что модуль передаёт, кроме кода и названия

Три поля, добавленные 5 сентября 2026. Каждое необязательно: если в базе
нужного регистра нет, поле просто не поедет, а обмен не упадёт.

| поле | откуда | что оживает |
|---|---|---|
| `companyExternalId` у накладной | `ЗаказПоставщику.Контрагент` | разделение товара по продавцам |
| `barcode` | регистр сведений со словом «Штрих» в имени | сканер и выгрузка остатков в 1С продавца |
| `reservedQty` | регистр накопления со словом «Резерв» | Аргус перестаёт предлагать чужой товар |
| остатки (`push/stock`) | регистр «ТоварыНаСкладах» | **Аргус впервые узнаёт, сколько товара на складе на самом деле** |

Имена регистров в конфигурациях разные, поэтому модуль их **ищет по
метаданным**, а не знает наизусть: берёт первый регистр, у которого в имени
есть нужное слово и есть измерение «Номенклатура». Что именно нашлось —
показывает кнопка **«Проверить базу»**.

### Порядок при первом запуске

1. **Подключиться** — ключ интеграции.
2. **Проверить базу** — посмотреть, нашлись ли контрагент, штрихкоды, резервы
   и остатки, и чего не хватает в самих данных (вес, штрихкоды, дубли
   артикулов). Отправляет ноль байт и менять ничего не может — нажимать
   безопасно в любой момент. Если что-то «НЕ НАЙДЕН», пришлите этот текст — значит в вашей
   конфигурации регистр называется иначе, и правку надо дописать под неё.
3. **Отправить контрагентов** — обязательно ДО накладных: накладная ссылается
   на контрагента по идентификатору, и без него строка вернётся с ошибкой
   «Компания не найдена».
4. **Отправить номенклатуру.**
5. **Отправить накладные.**
6. **Отправить остатки** — после номенклатуры: остаток кладётся к карточке
   товара и не создаёт её.

Повторный запуск ничего не дублирует: каждая запись находится по своему
идентификатору из 1С. Отправлять можно сколько угодно раз.


## Про остатки отдельно

До 5 сентября 2026 обмен остатки **не передавал вообще**, и Аргус не знал о
складе ничего настоящего: то, что лежало у него в ячейках, оказалось разовой
вставкой демо-данных и было стёрто.

Теперь остаток из 1С приезжает и живёт **рядом** с тем, что Аргус знает по
ячейкам, а не вместо него. Это два разных факта:

- **«в 1С числится 500»** — сколько всего товара на складе. Это знает 1С.
- **«по ячейкам разложено 480»** — сколько физически размещено по адресам.
  Это знает Аргус, и узнаёт он это только когда работник туда что-то положил.

Разложить итог 1С по ячейкам самим — значит выдумать адреса, а именно из-за
такой выдумки и пришлось стирать 879 строк. Расхождение между двумя числами не
ошибка, а полезная информация: «двадцать штук числятся, но по ячейкам не
разложены».
