# Аргус — модуль 1С

Для 1С:Управление торговлей **10.3** (обычные формы), платформа 8.3.

## Основной модуль

**`СинхронизацияАргус.bsl`** — весь модуль. Подключается к
`https://api.argus-ai.online` по ключу интеграции и отправляет контрагентов,
номенклатуру, накладные и остатки. Документы 1С не создаёт и не меняет:
**только читает и передаёт наружу** по HTTPS.

Раньше файлов было два — второй писал JSON на диск, чтобы посмотреть данные
до отправки. Он слит сюда: то же самое делают кнопки **«Проверить базу»**
(сводка на экран, ничего не пишет) и **«Выгрузить в файл»** (тот же JSON на
диск). Держать две обработки, собирающие одно и то же двумя разными кусками
кода, — верный способ однажды получить в файле одно, а на сервере другое.

## Если `.epf` уже собран — просто обновить

Обновляйте именно тот `.epf`, путь к которому указан в действующем задании
Планировщика. Предварительно сохраните его резервную копию. Имя файла может
быть `argus_sync.epf` или `АргусСинхронизация.epf`; новый файл создавать не нужно.

1. На той же машине: **Конфигуратор** → «Файл» → «Открыть» → выбрать этот `.epf`
2. Слева в дереве: «Формы» → двойной клик на форме → откроется картинка формы
3. Внизу окна вкладка **«Модуль»** → выделить весь текст (Ctrl+A) → вставить
   поверх новый из `СинхронизацияАргус.bsl` (Ctrl+A, Ctrl+V)
4. Если перечисленные кнопки уже есть, менять форму не нужно. Иначе вернуться
   на вкладку **«Диалог»** и добавить недостающие. Каждая делается
   одинаково: правой кнопкой на форме → «Вставить элемент управления» →
   «Кнопка» → в свойствах справа заполнить «Заголовок» и «Действие»:

   | Заголовок (что видно) | Действие (что вписать) |
   |---|---|
   | Проверить базу | `ПроверитьБазуВыполнить` |
   | Отправить остатки | `ОтправитьОстаткиВыполнить` |
   | Выгрузить в файл | `ВыгрузитьВФайлВыполнить` |

   Поля ввода добавлять не нужно — путь файла зашит в модуле.
5. **Ctrl+S** → закрыть Конфигуратор
6. Проверить: открыть тот же `.epf` уже в 1С:Предприятии (не в Конфигураторе):
   «Файл» → «Открыть» → ключ → «Подключиться» → **«Проверить базу»**

Если при сохранении 1С ругается красным — не гадать, прислать мне текст ошибки
целиком: там всегда есть имя и номер строки, по ним видно причину за минуту.

## Как собрать `.epf` с нуля (если его нет)

Внешняя обработка — отдельный файл, конфигурация базы не меняется.

1. Конфигуратор → **Файл → Новый → Внешняя обработка**
2. Имя: `АргусСинхронизация`
3. Правой кнопкой на «Формы» → **Добавить** → Форма обработки →
   **Готово** (обычная форма, не управляемая)
4. На форму положить:
   - поле ввода, реквизит формы **`КлючИнтеграции`**, тип Строка
   - надпись (Label), реквизит формы **`СтатусПодключения`**, тип Строка —
     просто для отображения текста, править вручную не нужно
   - семь кнопок, у каждой в свойстве «Действие» указать:
     - **`ПодключитьсяВыполнить`**
     - **`ПроверитьБазуВыполнить`** — ничего не отправляет, показывает, что
       модуль вообще нашёл в этой базе. Нажать первой.
     - **`ОтправитьКонтрагентовВыполнить`**
     - **`ОтправитьНоменклатуруВыполнить`**
     - **`ОтправитьНакладныеВыполнить`**
     - **`ОтправитьОстаткиВыполнить`**
     - **`ВыгрузитьВФайлВыполнить`** — записать всё в JSON на диск, ничего
       не отправляя
5. Открыть модуль формы, вставить весь текст из `СинхронизацияАргус.bsl`
6. **Файл → Сохранить как** → `АргусСинхронизация.epf`

## Как запустить

1. **Файл → Открыть** → `АргусСинхронизация.epf`
2. Ввести ключ интеграции из раздела **«Интеграция 1С»** кабинета владельца
   склада → **«Подключиться»**
3. **«Отправить контрагентов»** — сначала их. Они появятся как справочник
   для выбора и сами по себе не создадут тысячи компаний-продавцов.
4. Свяжите компанию с контрагентом в кабинете владельца Аргуса.
5. **«Отправить номенклатуру»**, затем **«Отправить накладные»**, затем
   **«Отправить остатки»**, каждый раз дожидаясь результата.

После каждой отправки — окно со сводкой: сколько создано, обновлено,
и сколько с ошибкой.

## Как товар получает продавца

У номенклатуры УТ 10.3 обычно нет надёжного стандартного реквизита владельца.
Поэтому модуль не угадывает продавца по названию и не складывает весь товар в
тестовую компанию. Владелец склада один раз связывает созданную в Аргусе
компанию с контрагентом 1С. Связь выбирается в списке компаний в кабинете.

Номенклатура сначала может прийти без продавца. Когда приходит заказ
поставщику этого контрагента, позиции документа получают связанную компанию.
У каждой позиции передаётся устойчивый идентификатор ссылки 1С, поэтому
одинаковые артикулы у разных продавцов не смешиваются. Если данные
неоднозначны, Аргус оставляет позицию без продавца и показывает её в счётчике
**«Без продавца»** вместо тихого назначения не той компании.

Вес пересчитывается из килограммов (стандарт УТ 10.3) в граммы —
если в вашей базе единица другая, поправьте до первой реальной отправки.

## Автозапуск по расписанию (Планировщик заданий Windows)

Вместо ручного нажатия трёх кнопок обработка теперь умеет отработать сама:
если `АргусСинхронизация.epf` запущен с параметром командной строки `/C`,
модуль читает его как ключ интеграции, молча (без диалоговых окон)
подключается и отправляет контрагентов → номенклатуру → накладные → остатки
(включая адреса и справочник ячеек), пишет результат в файл `argus_sync.log`
во временном каталоге пользователя, запустившего 1С, и закрывает сеанс. Обычное
открытие через «Файл → Открыть» не меняется — это работает только при
запуске из командной строки.

**Это касается сервера 1С клиента** — все шаги ниже выполняются вручную по
RDP на той же машине, где стоит база (или через кого-то с доступом к ней).
Исходный текст модуля можно подготовить удалённо, но сохранить его внутрь
`.epf` нужно в Конфигураторе 1С на этом сервере.

Шаги:

1. Скопируйте на сервер 1С папку с `АргусСинхронизация.epf` и шаблон
   [`АвтозапускСинхронизации.bat.example`](АвтозапускСинхронизации.bat.example)
   из этого репозитория.
2. Переименуйте `.bat.example` → `.bat`, заполните все `<ПЛЕЙСХОЛДЕРЫ>`
   реальными путём к `1cv8.exe`, адресом сервера/базы, логином и паролем
   1С-пользователя, ключом интеграции Аргуса (выдаётся в личном кабинете
   владельца) и путём к `.epf`.
3. Проверьте `.bat` вручную — он должен завершить обмен и закрыться. Длительность
   зависит от базы и сети; сравните время начала и окончания в журнале.
4. Зарегистрируйте в Планировщике (пример — раз в 30 минут, поправьте
   `/SC MINUTE /MO 30` под нужный интервал после замера полного обмена):

   ```
   schtasks /Create /TN "Argus1CSync" /TR "C:\ArgusSync\argus_sync.bat" ^
     /SC MINUTE /MO 30 /RU "<ПОЛЬЗОВАТЕЛЬ_WINDOWS>" /RP "<ПАРОЛЬ_WINDOWS>" /RL HIGHEST
   ```

   Пользователь Windows, под которым выполняется задание, должен иметь
   право «Вход в качестве пакетного задания» (Log on as a batch job) —
   Планировщик выдаст об этом явную ошибку при регистрации, если права нет.

5. В свойствах задания, **Параметры**, при уже работающем задании выбрать
   **«Не запускать новый экземпляр»**. Это исключает одновременную отправку
   двух полных снимков. Интервал должен быть больше обычного времени обмена.
6. Проверить как минимум два последовательных автоматических запуска.

Если запуск использует `/P`, пароль 1С находится в `.bat` и командной строке.
При настроенной аутентификации Windows используйте её без `/N` и `/P`.
Учётная запись обмена должна иметь только нужные права чтения 1С. Каждый
запуск занимает лицензию 1С на время сеанса.

### Проверка существующего задания без раскрытия ключей

На сервере 1С под учётной записью обмена запустите:

```powershell
powershell -NoProfile -File .\ПроверитьАвтообмен.ps1
```

Скрипт только читает состояние заданий с «Argus»/«Аргус» в имени и сводку
журнала модуля #12. Он не показывает команды запуска, пароли, ключи и старые
строки журнала. Если задание называется иначе, передайте `-TaskName '\Имя'`.
Если журнал находится в другом месте, укажите `-LogPath 'полный путь'`.

Критерий исправного обмена: повторяются запуски с `Режим: automatic`, каждому
соответствует `Завершение автообмена`, число ошибок равно нулю, в Аргусе
обновились этапы обмена. `LastTaskResult = 0` сам по себе не доказывает, что
все строки приняты: платформа может завершиться штатно после ошибки API.
Непривязанные контрагенты показываются отдельно и не объявляются сетевой ошибкой.
`PreventsOverlap` должен быть `true`.

## Возможные препятствия

- Открытие внешних обработок может быть запрещено политикой базы
- **Сеть**: неизвестно, пускает ли эта 1С исходящий HTTPS наружу —
  выяснится только на первом запуске «Подключиться»
- Если конфигурация доработана, состав реквизитов может отличаться. Поддержка
  проверяется для адаптера УТ 10.3; другие конфигурации не объявляются совместимыми
  автоматически.


## Что модуль передаёт, кроме кода и названия

Три поля, добавленные 5 сентября 2026. Каждое необязательно: если в базе
нужного регистра нет, поле просто не поедет, а обмен не упадёт.

| поле | откуда | что оживает |
|---|---|---|
| `companyExternalId` у накладной | `ЗаказПоставщику.Контрагент` | определяет продавца через подтверждённую связь в кабинете |
| `productExternalId` | ссылка `Справочник.Номенклатура` | не смешивает одинаковые артикулы разных продавцов |
| `barcode` | регистр сведений со словом «Штрих» в имени | сканер и выгрузка остатков в 1С продавца |
| `reservedQty` | регистр накопления со словом «Резерв» | Аргус перестаёт предлагать чужой товар |
| остатки (`push/stock`) | регистр «ТоварыНаСкладах» | учётное количество для сверки с физическим остатком Аргуса |

Имена регистров в конфигурациях разные, поэтому модуль их **ищет по
метаданным**, а не знает наизусть: берёт первый регистр, у которого в имени
есть нужное слово и есть измерение «Номенклатура». Что именно нашлось —
показывает кнопка **«Проверить базу»**.

### Порядок при первом запуске

1. **Подключиться** — ключ интеграции.
2. **Проверить базу** — посмотреть, нашлись ли контрагент, штрихкоды, резервы
   и остатки, и чего не хватает в самих данных (вес, штрихкоды, дубли
   артикулов). Отправляет ноль байт и менять ничего не может — нажимать
   безопасно в любой момент. Если что-то «НЕ НАЙДЕН», пришлите этот текст — значит в вашей
   конфигурации регистр называется иначе, и правку надо дописать под неё.
3. **Отправить контрагентов** — обязательно до настройки связей.
4. В кабинете владельца открыть список компаний, нажать **«Связать с
   контрагентом 1С»** и выбрать нужную строку справочника.
5. **Отправить номенклатуру.**
6. **Отправить накладные.** Они назначат товары подтверждённым продавцам.
7. **Отправить остатки** — после номенклатуры: остаток кладётся к карточке
   товара и не создаёт её.

Повторный запуск ничего не дублирует: каждая запись находится по своему
идентификатору из 1С. Отправлять можно сколько угодно раз.


## Про остатки отдельно

До 5 сентября 2026 обмен остатки **не передавал вообще**, и Аргус не знал о
складе ничего настоящего: то, что лежало у него в ячейках, оказалось разовой
вставкой демо-данных и было стёрто.

Теперь остаток из 1С приезжает и живёт **рядом** с тем, что Аргус знает по
ячейкам, а не вместо него. Это два разных факта:

- **«в 1С числится 500»** — сколько всего товара на складе. Это знает 1С.
- **«по ячейкам разложено 480»** — сколько физически размещено по адресам.
  Это знает Аргус, и узнаёт он это только когда работник туда что-то положил.

Разложить итог 1С по ячейкам самим — значит выдумать адреса, а именно из-за
такой выдумки и пришлось стирать 879 строк. Расхождение между двумя числами не
ошибка, а полезная информация: «двадцать штук числятся, но по ячейкам не
разложены».

Версия `2026-09-10 #11` передаёт и нулевые остатки. Если товар закончился,
Аргус получает явный ноль и не оставляет вчерашнее значение. То же относится
к резерву: найденный регистр позволяет передавать ноль и очищать старый резерв.

## Изменения `2026-09-11 #12`

- Запросы отмечены версией модуля и режимом `manual`/`automatic`. Это помогает
  отличить ручную проверку от действующего расписания.
- Ключ `/C` больше не пишется в журнал. Лог — в `КаталогВременныхФайлов()`
  учётной записи запуска; он содержит начало, этапы, завершение и число ошибок.
- Ошибка чтения резерва не заменяет его нулём. Резервы сопоставляются по ссылке
  номенклатуры, а не по потенциально повторяющемуся коду.
- Документы отправляются пакетами до 500. Непривязанные контрагенты обозначены
  «Ждут связи контрагента с продавцом»; повторная отправка справочника сама
  по себе эту связь не создаёт.
- Передаются тип исходного документа `supplier_order` и его дата из 1С.
  Заказ поставщику не подтверждает физическую приёмку товара.
- Все адреса одного товара находятся в одном пакете. Если их больше 500,
  адреса этого товара не отправляются, старый набор сохраняется и выводится
  явное сообщение о лимите.
- В ошибке остатка показаны исходное число, его тип и ID номенклатуры. Принятое
  отрицательное учётное значение отмечается отдельно; оно не становится
  физическим остатком Аргуса и не изменяет ячейки.

Исходный `.bsl` проверен статическими тестами. Для установки требуется сохранить
его внутри существующего `.epf` в Конфигураторе и проверить компиляцию на
сервере 1С. Наличие обновлённого файла на сайте не означает, что обновлена
запускаемая обработка или подтверждён планировщик.

Ограничение адресного снимка: если источник вообще не вернул адресов по
товару, текущий протокол не отличает пустую раскладку от отсутствующих данных
и не стирает прежние адреса. Их `synced_at` — время последнего получения,
а не подтверждение актуальности всей раскладки. Для полного очищения пустых
раскладок нужен отдельный признак успешно прочитанного полного снимка;
отсутствие строк нельзя трактовать как разрешение удалить адреса.
